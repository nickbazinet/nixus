## Orchestrator decisions

- O-1: Story builds run in per-story git worktrees (isolates from the owner's checkout and its untracked planning files; `bmad-build` sees a clean tree).
- O-2: Merges whose diff touches `apps/web/**`, `packages/shared/**`, `apps/api-bedrock/**`, `pnpm-lock.yaml`, `web-ci.yml` or `api-bedrock-ci.yml` are squash-merged with `[skip ci]` in the commit body so the production website and the Bedrock stack are NOT auto-deployed (owner rule "do not touch apps/web deploys" / "Bedrock stack must not be modified"). PR-time checks still run and must be green.
- O-3: `sync-infra.yml` deploys with `--disable-rollback` so that a failed first create leaves a repairable `CREATE_FAILED` stack instead of an undeletable-without-delete `ROLLBACK_COMPLETE` stack (owner rule: never delete stacks). Additive to the owner's command line.
- O-4: `bmad-build` is run unattended: every HALT/"ask the human"/approval checkpoint is auto-resolved by the builder and recorded; editor-opening steps are skipped.

- O-5: Owner message mid-run: "no need to update PR in the future. just merge to master". Applied as: builders push NO post-green / docs-only / ledger commits to a PR; the orchestrator squash-merges as soon as the builder reports DONE with green checks and the validator returns PASS (MINOR findings never block: they are logged as open issues instead of looping on the PR). Only BLOCKER/MAJOR defects and CI failures cause further PR commits. Infra stories (2, 3) still validate before merge because merging deploys to AWS. Story 1 was merged by the owner before validation, so it is validated post-merge on master.

- O-6: Owner message mid-run: "keep reviewers at a minimum. I prefer implementation speed. this is taking too long". Applied as: NO per-story spec reviewers and NO per-story validators (Story 1 was validated before this message; the sole remaining validator is the mandatory final gate). Builders self-review once, merge their own PR right after local gates (no waiting for the 15-25 min macOS/Windows Desktop CI; master CI is watched after the fact and failures are fixed forward by the next builder), skip bmad-build's parallel review layers, and keep specs short. Infra stories still wait for the 2-3 min `sync-infra` verify job because merging deploys to AWS.
- O-7: Infra track (Stories 2 then 3: CloudFormation + sync-infra.yml, no cargo) runs concurrently with the desktop track (Stories 4..12) as one background builder session, because they touch disjoint files; the desktop track stays strictly sequential in id order. Story 5 waits for the stack outputs if they are not yet available.
