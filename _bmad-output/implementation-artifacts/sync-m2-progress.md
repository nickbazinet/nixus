## Decisions & conflicts (append-only; format `- [story N] text`)

- [story 13] CONTRACT for Story 15+ — CLOCK (`sync/clock.rs`, production code, AD-4): `Hlc { time: u64 /* raw uhlc NTP64 */, install: InstallBytes }` with `Ord` WRITTEN OUT as (time, install bytes) — uhlc`s own `ID` orders little-endian and is deliberately never relied on; `Hlc::{ntp_time, wall_ms, install, encode, decode}`; `InstallBytes::{parse, hex}` (16 lowercase hex chars, reusing Story 6`s `new_install_id`, not duplicating it); `Clock::{new, with_wall_clock, install, now, observe}`; `WallClock = Arc<dyn Fn() -> i64 + Send + Sync>` in ms since the epoch; `system_wall_clock()`; `ClockError::{Skew{ahead_ms}, MalformedInstallId, MalformedTimestamp}` + `code()` -> `clock_skew | install_malformed | hlc_malformed`; `MAX_FORWARD_DRIFT = 300 s`; `HLC_ENCODED_LEN = 33`. `now()` is strictly increasing even inside one millisecond; `observe()` refuses a remote stamp more than 5 min ahead and NEVER advances the clock on refusal. Four narrow commented `#[allow(dead_code)]` name Story 15 (Story 24 for `ClockError::code`).
- [story 13] ENCODING FROZEN (Story 14 persists it): `Hlc::encode()` is exactly 33 chars, `{ntp64:016x}-{install:016x}`, fixed width and lowercase so a plain `ORDER BY`/`BTreeMap` over the TEXT reproduces the HLC order with no decoding. `the_encoding_is_frozen` pins the literal `123456789abcdef0-0a1b2c3d4e5f6071` and `the_encoding_sorts_exactly_like_the_clock` pins the order property over 200 stamps from two installs. Changing the width, padding, case or separator is a migration, not a refactor.
- [story 13] TRAP, uhlc 0.9.0: `HLCBuilder::with_clock` takes a bare `fn() -> NTP64`, NOT a closure, so a per-instance wall clock cannot be passed. The wall clock is therefore installed in a THREAD-LOCAL for the duration of each call into uhlc, behind a `Drop` guard so a panicking assertion cannot leave a foreign clock installed. Production installs the system clock through the same path, so there is one code path and no test-only branch, and N replicas with N clocks coexist on one thread (`clocks_on_one_thread_do_not_share_their_wall_clock`). SECOND TRAP: `HLCBuilder::new()` goes through `Default`, which reads `UHLC_MAX_DELTA_MS` and PANICS on a non-numeric value — the limit is always set explicitly with `with_max_delta`, so that variable must stay unset (noted in Cargo.toml).
- [story 13] TRAP: `NTP64` is not millisecond-quantised, so a drift of exactly `MAX_FORWARD_DRIFT` rounds either way. The tests assert a second inside and a minute outside the limit on purpose; tightening them to the boundary millisecond pins a rounding artefact and goes flaky. uhlc`s own exact NTP64 check is still called and still honoured — it is what guarantees the clock is not advanced on `Err`.
- [story 13] CONTRACT — SIMULATOR ENTRY POINTS (`sync/sim/`, all `#[cfg(test)]`): `runner::run(&SimConfig, Mutation) -> Result<SimOutcome, String>` (reference engine) and `runner::run_with(&SimConfig, |index, install, db_path, wall| -> Result<E: ReplicaEngine, SimError>)` (any engine — this is what Stories 15/16/19/20/21 call). `SimConfig { seed, replicas, steps }`; everything about a scenario is DERIVED FROM THE SEED (`replicas = 2 + seed % 4`, `steps = 40 + (seed >> 7) % 121`), so one u64 is a complete replay instruction. `SimOutcome` counts ops/segments/deliveries/duplicates/drops/offline periods/deletes/live rows and `the_fault_model_actually_fires` asserts every counter is non-zero over 12 seeds, so the gate cannot pass vacuously.
- [story 13] CONTRACT — ENGINE SEAM: `sync::sim::engine::ReplicaEngine { type Segment: Clone + Debug; local_write(&Change) -> Hlc; flush() -> Option<Segment>; deliver(&Segment); observable() -> Observable; pending_count() -> usize; }` plus `SimError::{Sql, Clock, Model}`. FOUR VERBS, no opinion about merge rules, encoding, storage or transport. `local_write` returns the HLC it stamped because the ORACLE computes the expected winner from the op log alone — "all replicas are identical" would also be satisfied by all of them being identically wrong. `Observable = BTreeMap<Table, BTreeMap<RowUuid, BTreeMap<&str, SimCell>>>` is in UUID SPACE (AD-2): the reference engine translates integer ids with its in-memory map, a `sync_uuid`-backed engine translates with the side table, and the comparison does not change. SWAP PROCEDURE is in the module docs of `sync/sim/mod.rs`: add an impl, parameterize the scenario tests over both, DELETE NOTHING — if a property has to be weakened for the real pipeline, the pipeline is wrong.

- [story 13] MERGE DECISIONS the reference engine froze (every later story must match them or change them here deliberately): (1) a TOMBSTONE IS ABSORBING per row uuid — an upsert of any clock value after it is dropped, which is sound precisely because AD-2 removes the uuid mapping with the tombstone, so a re-insert is a NEW identity (`action_reinsert`); (2) a child message whose parent is tombstoned is DROPPED, one whose parent has not arrived is PARKED (AD-11/AD-12) — parking the first would wait for a row that is never coming; (3) a cause-keyed balance delta keeps the MINIMUM-HLC copy of a duplicated cause, because a rule beats arrival order and every replica must agree on whether a later `balance_set` absorbed it; (4) a counter`s value is `1 + sum(deltas)`, the `1` being the schema default the row was created with. EVERY piece of merge state is KEYED (field by (table,row,column), delta by cause, counter by message id, tombstone by row), so idempotence is STRUCTURAL rather than a de-duplication pass bolted on.
- [story 13] ASSERTIONS after the full sync (these are the executable spec; they must stay green and must not move): identical `Observable` on every replica; no replica still holding a pending message; every LWW field equal to the max-HLC write with the install-id tiebreak; every balance equal to `latest balance_set + sum of deltas stamped after it`; re-delivering EVERY segment to EVERY replica in a fresh shuffled order changes nothing; every deleted row absent everywhere; a double delete equal to a single delete. The chaos phase advances the shared wall clock by `0 or 1` ms per step on purpose, so two replicas land on the same millisecond and the install-id tiebreak is exercised instead of being dead code.

- [story 20] DECISION — THE LOG IS THE MERGE STATE FOR THE TWO INCREMENT KINDS, and this is the central design choice of the story.
