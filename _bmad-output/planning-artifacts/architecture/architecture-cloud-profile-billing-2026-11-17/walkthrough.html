Context

Why this spine exists

The profile is the last piece of identity that never leaves the device — and the only place a subscription can later attach.

Today
  • Profile is a local JSON document per Cognito sub at app_data_dir/profiles/<sub>.json (schema v1).
  • The avatar is a separate SQLite file, profiles/avatars.db, one row per sub.
  • Lifecycle is independent of datasets: excluded from backups and from multi-device sync — the sync spine defers it as “needs a separate decision and mechanism”.
  • Removed by delete-all.
GoalInvestigation, goal statement
  • Move the user profile into the cloud so it can be managed from the desktop app and a new web account page.
  • That is the foundation for managing subscriptions and payments on both the web and the app.
  • Every Nixus Cloud account gets a profile — it is identity, not a premium capability (AD-2).
  • Users who want no account keep local profiles with on-device demographics (AD-6).
Not in this spineCAP-7
  • Billing and payments are a later, separate spine. This run reserves hooks only.
  • Reserved DynamoDB sort keys ENTITLEMENT and BILLING_CUSTOMER on USER#<sub> (AD-4); the profile Lambda's IAM policy cannot reach them.
  • AD-17 fixes the entitlement principle the billing spine must obey; nothing is built against it here.
  • Mobile purchases, account deletion and the erasure path stay deferred.
Dependency direction is one-way: surfaces → Profile API → profile table. Neither the account app nor the desktop depends on the profile table, and the profile Lambda depends on no surface.

Architecture

Design paradigm and system overview

Cloud-authoritative profile service with read-through device caches, plus a backend-for-frontend web account app.

Profile service

Stack nixus-account is the only writer and the only validation authority for a Nixus Cloud profile. Every surface is its client.

Desktop

A client that keeps a read-only on-disk copy for instant render and connection loss, and never writes a Nixus Cloud profile locally first. Local datasets keep demographics on the device only.

Account app

account.nixusapp.com is a TanStack Start BFF. The browser holds one opaque session cookie; tokens and profile calls stay on the server.

Marketing site

nixusapp.com stays static and only links to the account app — a plain link with a neutral label.

AD-6, AD-7

Two homes for demographics, one field set, one resolver

Prevents local demographics leaking to the cloud, filename collisions, reading another account's file, a local profile touching the keyring, and orphaned personal data.

Nixus Cloud copyRead-through cache
  • profiles/<sub>.json — read-only.
  • Envelope { schema_version: 1, cognito_sub, version?, upload_declined?, …ProfileFields }.
  • version and upload_declined are #[serde(default)] options; schema_version stays 1.
  • Written only from a server response (AD-7), or as AD-8's decline flag.
Local documentOn device only
  • profiles/local/<dataset-id>.json — the editable on-device document.
  • Envelope { schema_version: 1, dataset_id, …ProfileFields }.
  • Never a legal upload body.
  • Deleted by delete_dataset_at; a launch sweep removes any local/ document whose id is absent from datasets.json.
Resolver & surface
  • Returns a source token: cloud:<sub> or local:<dataset-id>.
  • The local branch never resolves a subject or touches the keyring. The cloud branch requires commands::datasets::is_signed_in(active, current_subject()), and otherwise returns “no source”.
  • The token is threaded through the operation, is part of the frontend query key, and is re-checked against the active dataset before any write. TFSA room, AI context and the Profile page call the resolver and never choose a file themselves.
  • /profile branches on dataset kind first: a local dataset gets an editable form with no session; a cloud-linked dataset gets the session-gated cloud path. The Profile menu entry is visible for local datasets.
  • profile_store.rs owns the demographic documents and the single charset rule; avatar_store.rs is the only other accessor of profiles/. danger_zone calls their functions and never touches files itself.
Lifecycle matrixAD-7
EventEffect
Sign-outCopy and avatar cache retained; queries removed
Account switchOnly the new sub's copy is ever resolved
Dataset deleteThat dataset's local/<id>.json removed
Delete-all any datasetMachine-wide wipe of <sub>.json copies and avatars.db, plus only the active dataset's local/<id>.json. The cloud PROFILE/AVATAR are kept, and the confirmation copy says so.
MigrateNothing copied

Out of scope here: Migrate-to-Nixus-Cloud copies no demographics (the source local dataset keeps its document), and avatars remain Nixus Cloud-only. Existing session and dataset-authorization behaviour is unchanged.

Inherited: AD-13 of the Local Profiles spine — the demographic store sits in the global root, not inside a dataset directory. Still true; AD-6 adds a local/ subfolder in that same root.

AD-7, AD-8

Desktop flow, offline behaviour, and consent for a legacy upload

Refresh runs in Rust — never on a timer, never from an always-mounted component (inherited D11).

Refresh
  • Runs in Rust when a cloud-linked dataset is activated (launch or sign-in), when the Profile page opens, and after each successful save.
  • The avatar is fetched only when avatar_version differs from the cached version column in avatars.db.
  • A network failure keeps the last copy silently. reauthentication_required is not silent: the Profile page shows a re-sign-in state.
Save
  • PUT, then await success, then rewrite the copy from the response.
  • An unobserved response is resolved by GET and comparing values before anything is shown to the user.
  • A version_conflict reloads that resource and informs the user without asserting that another actor changed it.
  • Offline, the copy is shown with Save disabled. With no copy, the page shows a connect-to-load state.
AD-8 — consent before the first upload of a legacy profileCAP-4
  • Detection: a legacy document is a profiles/<sub>.json with schema_version == 1 and no version. Detected by a raw, non-mutating probe that never quarantines.
  • Prompt: asked once, after a successful GET returns null (so after any re-sign-in).
  • Accept: uploads with expected_version: null; the response replaces the file.
  • Decline: sets upload_declined: true; the user is never asked again.
  • Cloud already has a profile: the cloud wins and the copy replaces the legacy file.

Prevents date of birth and income leaving the device without consent, quarantining the document being looked for, and repeated prompts.

  • Attached to api.nixusapp.com by an ApiGatewayV2::ApiMapping with key v1/profile and a literal stage name. Longest match wins; the base path is stripped.
  • sub comes only from the authorizer's verified claims and must match a UUID shape before any key is composed. pk/sk never appear in a response.

Sort keyHolds

  • Every PUT carries a mandatory expected_version: number | null. null means create-only, conditional on attribute_not_exists(pk); a number is conditional on version = expected_version.
  • Any failed condition returns version_conflict with resource and current_version, read via ReturnValuesOnConditionCheckFailure: ALL_OLD. Never an overwrite.
  • Profile and avatar are never written in one operation; reads never carry avatar bytes.
  • The Lambda's IAM policy is limited to PROFILE/AVATAR, and the profile document never carries payment data.
Validation & avatar contractAD-5

Server validation is final

  • ISO 3166-1/-2 country ↔ subdivision cross-check; bracket allow-list.
  • Date not in the future; age 18–120.
  • Currency allow-list, with the asymmetric rule that a bracket without a currency is rejected (field = income_bracket_currency) while a currency without a bracket is allowed.
  • 16 KiB profile body ceiling.

Avatar contract — same on every surface

  • Wire shape { "mime_type", "data" } with base64 data; no filename on any route.
  • image/png or image/jpeg only; longest edge ≤ 256 px (read from the header); ≤ 64 KiB decoded; ≤ 96 KiB request body.
  • Each client produces the derivative; the server validates the exact contract, and avatar_store.rs's named CHECK constraints mirror it.
  • Reference data: one canonical packages/shared/data/iso3166.json — no frontend ships a copy; allow-lists are declared once in account.ts.
AD-13 closed error union — unauthorized · reauthentication_required · validation (+field, reason) · version_conflict (+resource, current_version) · payload_too_large · unsupported_media · rate_limited · unavailable. API Gateway GatewayResponses for UNAUTHORIZED, ACCESS_DENIED, EXPIRED_TOKEN, MISSING_AUTHENTICATION_TOKEN, THROTTLED, REQUEST_TOO_LARGE, DEFAULT_4XX and DEFAULT_5XX emit this envelope; an insufficient-scope 403 is reclassified as reauthentication_required by the desktop.

AD-10, AD-11

The web account app is a BFF

The browser holds one opaque session cookie. Tokens and profile calls stay on the server.

Cognito client
  • A confidential client with PKCE, defined in IaC together with an AWS::Cognito::ManagedLoginBranding resource.
  • Sole callback https://account.nixusapp.com/auth/callback; scopes openid email profile nixus-api/profile; the same auth.nixusapp.com domain as the desktop.
  • Token revocation enabled; access-token TTL 15 min.
  • The client secret lives in SSM Parameter Store SecureString, read at cold start, never in an env var, template or log.
AD-11 — the account server never touches profile storage
  • It reads and writes profiles only through https://api.nixusapp.com/v1/profile, using the user's access token.
  • IAM gives the account-app role nothing on the profile table, and the profile role nothing on the session table.
  • CI guards check both directions.
  • Prevents two writers and two validators of one entity.

Marketing site: its button is a plain link with a neutral label. Signed-in state on the marketing site is deferred.

Session securityAD-10
  • Per attempt: a CSPRNG state, an OIDC nonce and the PKCE verifier are stored in a single-use pre-auth record (10 min) bound to a __Host- cookie.
  • Callback: rejects a missing or mismatched state or nonce as non-recoverable.
  • Fixation: the session id is newly minted at authentication.
  • Open redirect: the post-login destination comes from a server-side allow-list of path constants; no request-supplied URL is ever echoed.
  • Cookie: one opaque cookie — __Host-, Secure, HttpOnly, SameSite=Lax.
  • Expiry: the row is keyed by SHA-256 of the cookie value and carries idle_expires_at (24 h) and absolute_expires_at (7 d), both checked on every read. The DynamoDB TTL only reclaims storage.
  • State changes: every one is non-GET and Origin-verified, and only an Origin-verified request extends the idle expiry.
  • Sign-out: deletes the row, calls /oauth2/revoke for that refresh token on the web client, and redirects to the Managed Login logout. GlobalSignOut/AdminUserGlobalSignOut are forbidden — web and desktop sessions are independent.

Prevents: tokens in browser script, login CSRF, session fixation, open redirects, web sign-out killing the desktop session, stale sessions being honoured, and a leaked client secret.

Inherited: per-attempt state verified on callback, independent of PKCE (architecture-login.md).

Risks and open items

Everything the spine explicitly defers, plus the one technical unknown that gates Epic F.

Deferred to the billing spineCAP-7
  • Billing and payments get their own spine. Provider leaning: Stripe Managed Payments as merchant of record — LemonSqueezy closes 2027-03-31; product-category eligibility still to be checked.
  • Checkout and the customer portal on the account server.
  • Webhook ingestion and the writer for ENTITLEMENT.
  • One entitlement home versus HostedAiTable's USER#<sub>/CONFIG.
  • The AD-17 signed statement.
  • Server-side sync gating and replacing the manual premium runbook.
  • The per-partition write ceiling on USER#<sub>.

Mobile purchases are deferred too — in-app purchase via RevenueCat keyed on sub, or link-out. Store rules are regional and in litigation.

Accepted for v1AD-14
  • No WAF. A regional web ACL (~$8/month) or the CloudFront flat-rate plan with bundled WAF, if abuse appears.
  • The stage throttle is API-wide, so one abusive sub can degrade others. Accepted for v1.
  • The cloud copy is not purged on sign-out. Revisit when the copy becomes the only on-device personal data for several accounts on a shared machine.
  • Cognito stays console-managed. When the pool and resource server move to IaC, import the resource server with both scopes in one template — never patch it.
  • One production environment. A staging environment is deferred.

Also deferred: avatars for local profiles · Google federation · moving sync-infra.yml/web-ci.yml off static keys · signed-in state on the marketing site · API Gateway routing rules (AWS now prefers them over API mappings for REST APIs).

The one technical unknownGates Epic F
  • Hosting spike (AD-14): before account-app stories start, a deploy spike must prove a 302 redirect, a __Host- Set-Cookie and a server-function POST all work through CloudFront → Lambda Web Function via OAC.
  • Why it is a risk: Lambda Web Functions are a current AWS service with Node runtimes only and an OAC origin; this repo has never run a server-rendered surface, and the entire BFF session design in AD-10 assumes cookies and server functions survive the CloudFront hop.
  • Version constraint: @tanstack/react-start is pinned at ~1.167.65 because ≥ 1.169 requires Vite 8 while the workspace is on Vite 7.3.2 — the spike must be run on the pinned pair.
  • Blast radius if it fails: Epic F's hosting changes; Epics A–E and the Profile API are unaffected.

Also verified before the first deploy: the api.nixusapp.com routing mode is an API-mapping mode, and the resource server holds both scopes.
