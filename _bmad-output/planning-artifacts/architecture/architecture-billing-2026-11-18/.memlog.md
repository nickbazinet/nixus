- (decision) B1 entitlement home is a dedicated billing table in a new stack, not the reserved ENTITLEMENT and BILLING_CUSTOMER sort keys in the profile table. Binds the entitlement authority. Prevents the profile Lambda role holding read-write reach over payment state, and three stacks writing one table. Declared departure from parent AD-4 reservation, justified because DynamoDB has no sort-key IAM condition so AD-4 sort-key isolation is only by code construction.
- (decision) B2 service topology is a new stack nixus-billing attached to api.nixusapp.com by ApiMapping key v1 slash billing, following parent AD-3. Prevents an unauthenticated webhook route sharing an API with Cognito-authorized routes, and prevents a second hostname.
- (decision) B3 only the billing Lambda holds Stripe credentials. The account BFF calls the billing API over HTTP with the user access token and never talks to Stripe or to billing storage directly. Generalizes parent AD-11 to billing. Prevents two Stripe key holders and two entitlement writers.
- (decision) B4 the signed entitlement statement is signed on write, not on read. The webhook signs once per entitlement change and stores the statement in the ENTITLEMENT item, the GET returns it and re-signs when at or near expiry. Prevents a per-request KMS cost and prevents a cancellation being outlived by a statement signed before it.
- (decision) B5 tier and price mapping comes from Stripe, not from code. Prices are referenced by lookup_key, tier identity comes from Product metadata.nixus_tier, and the per-tier capability list comes from Product metadata validated against the compile-time capability union. Prevents a price change or a discount requiring a deploy.
- (decision) B6 the public price catalog is served by an unauthenticated GET v1 slash billing slash plans, cached at CloudFront. The static marketing site ships baked fallback copy and hydrates over it. Prevents a stale advertised price after a Dashboard change, and prevents moving the pricing page off the static site.
- (decision) B7 the webhook converges rather than applying deltas. On any relevant event it re-fetches the subscription from Stripe and writes the derived entitlement, guarded by an event-id dedupe record and a monotonic watermark. Prevents out-of-order and duplicate delivery corrupting an entitlement.
- (decision) B8 the free Nixus Cloud tier is shown on the pricing page and sign-in works without a subscription. Prevents the page implying an account only exists once you pay.
- (decision) B9 monthly prices only at launch. Annual is a later Dashboard-only change. Prevents doubling the pricing-page states and proration cases before the first renewals clear.
- (decision) B10 the hosted-AI monthly request limit is per tier and read from the entitlement, not a single global value. Prevents Advance having no quota lever over Classic.
- (decision) B11 HostedAiTable.premium is retired rather than written by the webhook. The table keeps quota counters only. Prevents the two-sources-of-truth defect this spine exists to close.
- (decision) D1 the entitlement authority moves out of HostedAiTable entirely and the bedrock Lambda reads it from the billing table. Binds hosted AI. Prevents two answers to is this user entitled.
- (decision) D2 free is a first-class tier answered for every valid token and needs no stored record. An absent ENTITLEMENT derives free with an empty capability list and the response is still a signed statement. Prevents the desktop confusing verified free from could not reach the server, and prevents a write path for a state that has no paid data.
- (decision) D3 adding a tier must cost no deploy. Binds the tier model. Prevents a redesign when tier N plus 1 ships.
- (decision) D4 tier N plus 1 grants non-software perks fulfilled by a human, so tier must be legible to operations and not only to the UI. Prevents support being unable to tell who is owed faster support, while still forbidding a feature gate from branching on tier.
- (decision) D5 the pricing page keeps household net worth under Classic and custom dashboards under Advance. household_net_worth is reserved as a capability name and granted before any code consumes it. Prevents the capability union having to change when the household feature lands.
- (decision) D6 monthly only at launch, confirmed by the owner.
- (decision) D7 Adaptive Pricing is accepted and the pricing copy is reworded. Copy states a CAD list price shown in the visitor currency at checkout with tax included, and never says taxes extra. Prevents a footnote that contradicts what Stripe actually charges a non-Canadian visitor.
- (decision) D8 downgrades take effect at period end and no data is ever deleted on tier loss. Historical data is retained in full and the tier simply stops granting capabilities. Prevents a deletion path being built for a billing event.
- (decision) D9 re-subscribing after a lapse is a relink, not an incremental resume, reusing the sync spine existing link decision. Prevents a second merge engine for a diverged local and cloud state with no recent common ancestor.
- (decision) D10 the statement offline window is 24 hours with revalidation on app start and on sign-in, and dunning grace is Stripe Dashboard configuration rather than code. Prevents a cached statement being the reason an unpaid user keeps a paid feature, and prevents a short window locking out a customer mid-retry.
- (decision) D11 two frozen devices that both edited offline are accepted without a merge. Whichever relinks first publishes and the second is offered the existing link decision. Prevents building a merge path for a rare case the sync spine already has an answer for.
- (decision) D12 tier N plus 1 is perks-only for now and ships as a pure Stripe Dashboard change with Advance capability list. Prevents a speculative capability entering the closed union before a feature needs it.
- (decision) Gates read capabilities and never tier. Tier is a display and operations label only. Binds every surface including sync, hosted AI and the UI. Prevents a new tier requiring edits across feature code, which is what makes D3 and D12 true.
- (decision) The capability union stays closed at compile time in both billing.ts and entitlements.rs, with the webhook validating Stripe-supplied capability names against it and dropping unknown names with a loud log. Prevents an operator inventing a capability by typo, and keeps every gate exhaustive rather than a lookup that can miss.
